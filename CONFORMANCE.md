# Conformance — Janus-Facing Architecture

The repo's self-description in the architecture's own terms, stated **before** anything product-specific, per the architecture's ordering rule. Every conformance claim is bound to the mechanism and check that enforces it, or it is labeled a stand-in or stub. Unbound prose is marketing.

The architecture is **Janus-Facing Architecture (JFA)** — NTARI's unified architecture document, free documentation under the project's AGPL-3.0 commons.

## Role declaration

Cloudy is a **front end** of a JFA substrate — the member-facing application — and the home of the **member-economy layers** the substrate coordination protocol deliberately does not define: the per-operator dialog record, the reputation covenant, and member-issued credit. Members exist here and only here; the coordination wire below this repo knows no persons. Cloudy is a standalone, forkable product: it speaks the published protocol and any conformant coordinator can serve it.

| This repo's term | Architecture role |
|---|---|
| `internal/record` | the **per-operator dialog ledger** — append-only, dialog-sealed, witnessed |
| `internal/covenant` | the **assessment scale** implementation (member reputation as covenant) |
| `internal/economy` | **member-issued credit** (the member economy) |
| `internal/coord` | consumption of the substrate **coordination protocol** |
| `internal/enroll` | **frontend-as-operator enrollment** with a coordinator (apply → keys → verify → conformance → active) |
| Member | a person, platform-scoped; PII stays member-local and erasable |

## Invariants and their bindings — as of `main`

Statuses are stated per the architecture's honesty rule. Built member-layer work beyond this exists in the open PR stack and updates this table as it lands.

| Invariant (architecture) | Status on main | Mechanism / check |
|---|---|---|
| Record is **append-only**; corrections are new entries | **Built** | `internal/record`: Store/Log expose Append only — update and delete are absent verbs; package doc states the structural rules; tests |
| Record is **dialog-sealed** — what two members agreed, not what one asserts | **Built** | Dual-seal verification over canonical bytes; self-dialog rejected at construction |
| **No PII in the commons**; narrative stays member-local and erasable | **Built** | Commons types carry hashes, keys, and instants only; erasable content lives in a type-disjoint member-local store |
| **Witnessing** with structural independence; a single-witness deployment is a labeled stand-in | **Built (stand-in)** | Witness countersignatures with pairwise-independence verification; the StandIn label is computed, not asserted |
| Covenant: **never average**; full distribution; symmetric; gates whether-never-how-much | **Built, except the trust gate** | `internal/covenant`: full distribution per relation, never averaged (`TestInvariant_L8_NoScalarAggregation`); No Trust requires a justifying comment hash; answers annotate, never erase (`TestAnswersCloseTheSymmetryBreach`). "Never how much" holds: the credit limit is never derived from standing (`TestInvariant_L9_OperatorSetUniformLimit`). **Not yet wired:** "gates whether" — no spend path consults standing before admitting a trust-based trade |
| Economy: balances a **deterministic function of the sealed record**; zero-sum; escrow-first; earned-never-bought | **Built** | `internal/economy`: replay re-derives every balance (`TestOpenReplaysHistory`, `TestOpenDetectsTamper`); zero-sum (`TestInvariant_L1_ZeroSumBalance`); escrow-first, one governed switch (`TestPostRejectedInEscrowMode`, `TestModeSwitchIsOneRecord`); earned never bought (`TestInvariant_L2_EarnedNeverBought`); sovereign unit (`TestInvariant_L3_SovereignUnits`); one operator-set limit (`TestInvariant_L9_OperatorSetUniformLimit`) |
| **Single participant identity** — one member, simultaneously contributor and consumer | Design-binding | No producer/consumer split exists in any schema or type; binds every member surface as it lands |
| **Forkability** | Built | Consumes the coordination protocol at a published version tag; no coordinator is privileged |

## JFA registry bindings

Tests that bind an ID from the Janus invariant registry (`jfa-conformance-suite.py` in NTARI-RAND/Janus) are named `TestInvariant_<ID>_<Name>`, with any `-` in the ID written `_` (so `REC-six-holders` becomes `TestInvariant_REC_six_holders_…`). `go test -run TestInvariant_ -v ./...` lists every binding and its result.

| Registry ID | Test | What it adds beyond the package's existing tests |
|---|---|---|
| **REC-witness-minimum** — fewer than two independent witnesses forces the unfederated label | `internal/record` `TestInvariant_REC_witness_minimum_UnfederatedLabel` | The label is computed: it stays on for zero or one witness, and when the "second" is the operator, the same witness twice, a forged signature, or a cosignature of another checkpoint; it drops only for two verified, operator-independent witnesses. Every served struct with `countersignatures` also carries a `stand_in` bool, set from a `StandIn(…)` call, never a constant. Named exception: the relay's `BundleMsg`, which by design leaves counting to readers |
| **COV-adjudicators** — adjudication conduct ratable by the parties to the adjudication | `internal/consumerapi` `TestInvariant_COV_adjudicators_PartiesRateTheAdjudicator` | Both complainant and respondent can rate the operator's conduct; a stranger, a non-party trader, a party on an unclaimed exchange, and the operator itself cannot; the relation rates only the adjudicator; ratings form their own distribution, never pooled into trade; only the operator answers. **Residual:** the cross-platform half (witnesses rated as adjudicators) awaits witness-layer adjudication, which is not built |
| **COV-operators-adjudicate** — platform operators adjudicate | `internal/dispute` `TestInvariant_COV_operators_adjudicate_OperatorRulesOnItsPlatform` | Only a threshold of the platform Charter's adjudicators resolves a case — never a party, both parties, a witness, or a stranger; rulings are bound to their platform; the Registry API is pinned and `StateResolved` is set in exactly one place; a withdrawal is the complainant's alone and carries no finding. Out of scope, named: barring a rostered adjudicator from its own case is COV-operator-dispute-witnesses (instrument-bound) and is not enforced here |
| **SUB-no-inbound-requirement** — a node contributes without open inbound ports or a static address (node side; the wire is bound in sohocloud-protocol) | `cmd/cloudy-agent` `TestInvariant_SUB_no_inbound_requirement_AgentNeverListens` | No file in the agent or any Cloudy package it imports opens or serves on a listening socket (Listen*, ListenAndServe*, FileListener, FilePacketConn, a networking package's Serve), and none dot-imports a networking package; the agent → coordinator loop lists, heartbeats, polls, runs, reports and declines over the reference HTTP+JSON wire, every call made by the node. **Residual:** a real NAT/CGNAT path is a Phase 2 multi-node test |
| **L1** — each exchange moves two balances netting to zero | `internal/economy` `TestInvariant_L1_ZeroSumBalance` | Concurrent payers across two ledgers sharing one store; per-record netting; replay reproduces every balance |
| **L2** — earned never bought, never redeemable for fiat | `internal/economy` `TestInvariant_L2_EarnedNeverBought` | The ledger API, record union, and every record field are pinned to allowlists; the ledger imports only the standard library and canon; no buy/redeem/cash-out/payout verb or route exists in the module, and no function both touches the fiat rail and builds a spend; at runtime escrow holds no credit and a balance rises only by a payer-signed spend |
| **L3** — sovereign units, no conversion | `internal/economy` `TestInvariant_L3_SovereignUnits` | One key yields unlinkable accounts per platform; a spend signed for one platform never posts on, or re-points to, another, and a foreign spend in a store makes it refuse to open; platform identity lives in no governed field; no conversion, rate, peg, or bridge surface exists |
| **L6** — no update-in-place, no delete; dismissal is annotation | `internal/record` `TestInvariant_L6_AppendOnly` (dismissal half: `internal/covenant` `TestAnswersCloseTheSymmetryBreach`) | A correction appends and leaves the corrected entry and all earlier proofs intact; an in-place rewrite done directly on storage fails consistency against a checkpoint taken before it; a module-wide source scan finds no update or delete verb on any append-only type — tracked by name (Store/Log/Ledger/Book) or by an "append-only" doc comment, with `market.Catalog` and `techtree.Tree` pinned so they cannot drop out of scope |
| **L7** — commons holds hashes, types, timestamps, references only | `internal/record` `TestInvariant_L7_CommonsSchema` | Every commons type, field by field, admits only byte arrays, unsigned integers, `time.Time`, and `[]byte` fields named in an explicit allowlist of ed25519 keys and signatures — no string, map, interface, float, or unlisted `[]byte`; every allowlisted field, padded with a memo, fails verification against a passing unpadded control and never enters a log |
| **L8** — full distribution carried; no scalar score anywhere | `internal/covenant` `TestInvariant_L8_NoScalarAggregation` | Two members with equal means and different shapes stay distinguishable; a module-wide source scan for score-named or float-returning exported functions, score-like JSON tags, and float fields in reputation packages |
| **L9** — one uniform limit, set by the operator, never from reputation | `internal/economy` `TestInvariant_L9_OperatorSetUniformLimit` | Policy carries exactly one limit and nothing per-account; members and operator-held keys hit the same floor before and after a change; only the Genesis stewards' quorum moves it; the ledger cannot import the covenant and no function that sets the limit reads standing (residual named: a limit computed from standing in a separate helper is not seen by the per-function scan) |

## Stand-ins and open residuals

- **Single-witness StandIn.** Every witnessed checkpoint today has fewer than two independent witnesses; the record layer computes and reports this label structurally. Live federation is the architecture's open problem 2 — the keystone build.
- **Covenant trust gate not yet wired.** Covenant and economy are built on main and bound to registry tests (see above). The one open half is the covenant's "gates whether": no spend path yet consults a member's standing before admitting a trade on trust. "Never how much" is enforced; "whether" is a named gap, not a claim.
- **Record domain-tag rename** (product naming) is pending and must land **before any durable persistence** — retagging after durable logs exist would be a rewrite.
- **Named record residuals** (steganographic floor, timestamp covert channel, witness amnesia, liveness gap) are documented in the record package doc rather than pretended away.
- **Contributor node — Executor seam built; runtime implementations pending.** `internal/contribute` fixes the node-contribution contract (Executor / ServiceExecutor / Registry / NodeContract) with two invariants enforced by tests: a scavenged node accepts only preemptible executors (owner-never-interrupted), and a Service workload requires pinned placement. `cmd/cloudy-agent` runs it end to end with a **real** Storage executor (opaque sealed shards + the `internal/storage` proof-of-possession) and **placeholder** Compute/Service executors. The **agent → coordinator loop is built** (`cmd/cloudy-agent/loop.go`, run with `-coordinator`): it lists the node, heartbeats, polls, runs accepted work through the seam, and reports or declines every assignment exactly once, all signed with the node's ed25519 key (`-node-key`, created mode 0600); assignments are verified against the coordinator's key (`-coordinator-key`) and a forged one is declined, never run; opt-out is enforced locally (SPEC §5.1); a scavenged node re-lists as offering nothing when its owner returns. Per [decision 0001](docs/decisions/0001-node-connects-through-its-frontend.md) the agent talks to its frontend: **the node relay is built** (`internal/noderelay`, served on cloudyd's `/v0` routes with `-orchestrator`). Each agent request carries a node request signature (fresh, never replayed, bound to the node the call names); only enrolled nodes are relayed; every node message is verified and forwarded unchanged under the frontend's operator credential, so its signature still verifies at the orchestrator; heartbeats reach the orchestrator at most once a minute per node and polls at most once every 30 seconds; node keys are enrolled with the orchestrator through the operator (SoHoLINK `POST /nodes/pubkey`). The direct SPIFFE route stays available. **Named gaps:** SoHoLINK still creates a node's record only through its participant claim flow, which ties the node to a person at the orchestrator — decision 0001 needs an operator-scoped node registration there (SoHoLINK follow-up); cloudyd's enrolled nodes come from a file (`-nodes`) and live in memory, a stand-in for member-driven enrollment; with the roll-up, the orchestrator's view of a node can lag by up to one roll-up window. Storage has no opt-in flag in the pinned protocol (v0.1.0), so storage work is accepted or declined locally only. The heavy runtime port from the coordinator's transitional `internal/agent` — Docker executor, gopsutil hardware sampling, opt-out/allowlist/printers — lands *behind* the executor seam without changing the loop.
- **Operator enrollment driver — built and live-verified.** `internal/enroll` + `cmd/cloudy-enroll` drive a coordinator's operator onboarding lifecycle end to end (apply → register the 7-key set → email verification → conformance suites A/B → automatic activation), reusing `internal/opcred` for key custody and for computing conformance answers through the real protocol canon. Suite C is graded coordinator-side and needs no operator response, so there is no suite-C step. The client is deliberately separate from `internal/coord`: enrollment is plain JSON on the coordinator's **portal** surface, not the `/v0` node-side wire. The out-of-band email code is supplied via an injected `CodeSource`. Verified against a live SoHoLINK coordinator — the enrolled operator reached `active` and its credential then authenticated on `/v0`.

## Dependency declaration

Consumes `sohocloud-protocol` at a published version tag — nothing else from the stack. The member layers reference sealed exchanges by opaque leaf ID, by value, never by importing record types into other layers; conversion happens only at the composition root.

## Product-specific notes (last, per the ordering rule)

Cloudy ships as a standalone consumer product (its own member API and app surfaces, in review). SoHoLINK is the reference coordinator it speaks to; any conformant coordinator may replace it.
